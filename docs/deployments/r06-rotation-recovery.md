# R06：按原任务恢复轮动发布

对应 #40，依赖 #38 和 #21。当前分支基于 PR #48，实现与审查完成，尚未合并、部署或操作生产数据库。原始工作区未修改。

## 行为

管理页在参考采集记录和相关 ETF 批次中展示原日期、阶段和恢复记录。浏览器只提交原采集日期或已保存任务 ID，不接收日期、对象、报价覆盖参数。

参考恢复使用冻结的原始输入及参数，成功参考不可替换。缺少原时点输入时明确“原时点数据无法补取”。收盘恢复通过同一 ETFService 重试失败对象和未完成步骤，保存实际重试批次 ID；同步完成后重新计算、发布原日期的四标的整组结果。三只成功、一只失败时展示 3/4，尚未完整同步时不发布新结果。重试再失败可由失败子任务继续，保留父子关系。

恢复记录按原任务查询，不受全局最近 50 条记录限制；每个原任务保留最近 50 次尝试供查看，明确父子任务标识。对正在执行的恢复再次请求重试时，在锁定采集记录之前立即拒绝，避免与发布流程形成反向锁等待。

请求接受、同步中、同步完成、计算中和发布完成是后端真实阶段。客户端关闭不取消后台工作；服务中断后沿用原批次继续。发布事务检查执行权及数据版本，旧执行者不能发布或改写新任务状态。管理代理要求 Access、同源及 CSRF，只转发严格允许的恢复路径，服务密钥不进入浏览器。

恢复结果链接定位原交易日，返回最新日期时清除历史日期参数。没有新增金融计算或操作建议，没有加入定投模拟。

## 可复现预览与验收

需要本地 MySQL 的专用 `candela_daily_test` 数据库。测试会清理该测试库，不得设置为生产数据库；不要与其他重置同一测试库的任务并行。

在 `web/frontend` 构建后运行：

```sh
ROTATION_DAILY_TEST_DSN='root@tcp(127.0.0.1:13316)/candela_daily_test?parseTime=true&loc=UTC' \
LD_LIBRARY_PATH=/tmp/candela-browser-libs/root/usr/lib/x86_64-linux-gnu \
FONTCONFIG_FILE=/tmp/candela-browser-fonts.conf \
npx playwright test --config playwright.recovery.config.ts
```

测试启动 `127.0.0.1:18090` 上的真实恢复/同步 API，以及 `127.0.0.1:18081` 上的真实 web 应用。临时签名登录凭证由测试生成，浏览器通过实际验证器访问 `/admin/data` 与 `/strategies/four-etf-rotation`。只在测试二进制中替换行情源、时间及临时数据库故障，生产不带测试入口。测试结束自动停止服务，不将该地址描述为长期在线预览。

## 双轴审查

### Standards

复核通过。`ed80dec` 将最近 50 条限制应用于原任务范围，旧失败任务可直接显示最新尝试并继续重试；活跃父任务在获取采集锁前返回 409，消除了所述锁顺序冲突。未发现新增的明确规范违反或值得报告的 Fowler smell。评审仅只读检查代码和相关断言，实际测试由主任务执行。

### Spec

复核通过，两项问题均已解决，未发现新增 Spec 问题。父恢复任务未失败时，在获取采集锁前返回 409，消除了正常运行中的重试与发布之间的反向锁等待；失败父任务的子重试与去重语义保留。恢复列表先按阶段和原任务筛选，再取最近 50 条，无关任务不再挤掉当前任务记录；生产路由、受保护代理及前端轮询均已接入。新测试覆盖发布暂停时及时拒绝重试、旧执行者不可发布，以及 51 条无关记录下仍可读取原任务。

最终剩余发现：Standards 0 项，Spec 0 项；两轴均无未解决问题。
