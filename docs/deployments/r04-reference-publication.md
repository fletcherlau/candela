# R04 · 固定参考发布与每日双时点读取

对应 [#38](https://github.com/fletcherlau/candela/issues/38)，依赖 R03 的固定输入。使用同一计算核心，前端只验证、格式化和展示结果。

## 发布边界

独立参考 worker 读取已完成的 `rotation_capture_run`，用已冻结历史、因子、日历、停牌依据、覆盖日期和参数计算。与收盘共用六指标计算入口；不缩短参数窗口填补历史不足，不从新行情或新日历重建原参考。首次结果、发布时间和管理状态在同一事务提交；重复执行及后续收盘更新不覆盖参考。旧冻结输入没有停牌证据时，未知缺口按缺失处理。

后台日线维护同时准备当天交易日历。每日 GET 在同一个只读数据库快照内读取日期、修订、两时点结果及采集进度，不请求外部源。鉴权入口仍为服务密钥；网页沿用 Cloudflare Access 与只读精确代理路径。

## 默认状态

| 后端事实 | 返回结果 |
| --- | --- |
| 交易日 14:45 前 | 明确日期的上一交易日及今日等待状态 |
| 今日参考排队、生成中、失败或缺失 | 上一交易日及今日进度／缺失原因；无上一日发布则为空 |
| 今日参考完整，收盘未齐 | 今日固定参考，保留 3/4 等收盘进度 |
| 今日两时点完整 | 同日两组指标及价格 bps |
| 收盘完整，参考缺失 | 今日收盘，参考与比较为空且说明原因 |
| 非交易日 | 最近已确认交易日以内的可用发布 |
| 所需日历缺失（包括回退区间） | calendar_unavailable，不按星期或现有价格猜日期 |
| 显式请求历史日期 | 保持原选择，不用别的日期替代 |

响应包括请求／实际日期、当前日期与交易日、选择方式、回退原因、两时点状态、缺失对象与原因、发布时间、参数和来源时间。前端只读刷新间隔 30 秒且仅在页面可见时进行；10 秒超时、最新请求保护、失败保留带日期的已读数据，均不阻塞回测区。

价格比较为 `(close-reference)/reference*10000`，后端仅在同日两组有效正价格存在时产生有限数值。前端按带方向的一位小数去尾零格式展示 bps，缺失保持空值。这是两时点行情差异，不是实际账户或实际成交滑点。

## 数据库与升级

迁移 v7 为 `rotation_daily` 添加可空 JSON `missing`，持久保存逐标的原因。所有迁移在既有数据库连接锁内执行；v7 先核对字段是否存在且为可空普通 JSON 列，再添加或确认。DDL 成功但版本记录未写入时，重启能够继续；不吞掉不兼容列定义。真实 MySQL 验收覆盖从 v6 升级、模拟 DDL 已提交但版本未登记、重复启动及原有发布仍可通过 HTTP 读取。

本票未执行生产迁移或修改 cron。部署时先备份生产库并核对当前版本，再由新服务启动执行迁移。原始输入留存及外部触发约束仍见 [R03 说明](r03-reference-capture.md)。

## 验收与未完成能力

[页面、截图与复现入口](../design/rotation-reference/README.md)。数据源真实时段稳定性仍需上线后观察，不能从测试 4/4 推断每天必达。当前集成没有历史 14:45 补取能力；历史日期入口（R05）、管理重试（R06）、历史更正传播（R07）分别由后续工单实现。每日页不输出变化原因推测、定投数据或操作结论。
