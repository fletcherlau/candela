# ADR-0001: 同步触发拓扑——调度交给系统 crontab，服务保持无状态

- 状态：已接受
- 日期：2026-08-03（issue #1 决策，2026-08-04 补录）

## 背景

ETF 日线数据需要每日更新。可选方案：(a) 服务内置调度器（cron library / ticker）；(b) 系统 crontab 调用服务暴露的 HTTP 接口；(c) 纯 CLI + crontab，无常驻服务。

## 决策

采用 (b) 的变体：

- syncer 是**常驻 HTTP 服务**，暴露 `POST /api/v1/sync/etf-daily` 触发接口（X-Api-Key 鉴权），但**内部不含任何调度逻辑**，保持无状态。
- 每日调度由 Linux **系统 crontab** 负责：一条带鉴权头的 curl 调用触发接口。
- 同一二进制支持 **one-shot 模式**（`-once`：跑完即退），作为服务不可用时的调试与恢复兜底通道；one-shot 与 HTTP 接口走同一个同步核心。

## 后果

- 调度配置（几点跑、失败重试策略）是运维层的 crontab，不进代码库，改时间不用发版。
- 服务无状态，重启/崩溃不丢失调度语义；手工补数与自动同步是同一个接口。
- 代价：cron 的失败通知依赖系统层（邮件/日志），服务自身不感知「今天有没有被触发」——巡检依赖 `GET /api/v1/sync/status`。
