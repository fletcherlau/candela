# ADR-0009: 外部 cron 触发与持久同步执行分离

- 状态：已接受
- 日期：2026-09-09
- 部分取代：ADR-0001 关于服务无状态、内部不含任何调度逻辑的约束；保留每日业务触发由系统 cron 负责的决定。

用户要求同步不依赖浏览器连接，支持排队、取消、仅重试失败对象及重启恢复，因此原有随请求执行且没有持久执行状态的方式不足以满足需求。syncer 新增基于 MySQL 的持久执行协调，保存固定对象与日期范围、分段检查点、执行权和取消状态；HTTP、机器人及 one-shot 入口均经过同一协调边界，避免绕过对象互斥。

每日何时发起同步仍由外部系统 cron 决定，按 Asia/Shanghai 的 18:00 触发；服务内只负责已提交工作的执行、排队及恢复，不新增每日业务定时器。该选择复用现有 MySQL，不引入额外消息队列；代价是需维护事务一致的检查点、执行权失效保护及可恢复工作状态，并使用真实数据库测试验证故障行为。此决策已获批准。T02 已实现中证全指的持久接受、排队、分段检查点与执行权失效保护；取消和自动恢复由 T03 完成，ETF／申万及其他入口随后迁入。详见 [T02 实现与验证](../deployments/t02-sync-runs.md)。

## 2026-09-21：中证全指取消与恢复落地

T03 在原对象锁与执行权之上增加持久取消意图、终态确认和事件记录。分段提交与取消共享锁，先取得锁的事务先提交；取消被接受后不得再写入新段。未取消的执行在正常停机或租约失效后重新取得执行权，沿用原起止范围、历史依据和检查点；已取消与最终失败任务不自动恢复。详情中的状态和事件从同一数据库快照读取。验证包含隔离 MySQL、真实子进程被终止与重建、迟到旧执行者以及受鉴权管理页。参见 [T03 验收](../deployments/t03-sync-recovery.md)。
