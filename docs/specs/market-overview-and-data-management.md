# Candela 市场总览与数据管理 · PRD

正式 issue：[PRD #17](https://github.com/fletcherlau/candela/issues/17)。

日期：2026-09-09。业务需求、实现方案与测试边界已由用户整体批准。正式 PRD 以 GitHub issue 为准；批准不代表已经实施或部署。

## Problem Statement

平台已有 ETF、申万数据同步和轮动信号能力，但缺少统一的网站入口、中证全指市场环境视图及可直接操作的数据管理页面。现有同步随请求执行，缺少可持久查询、取消、重启恢复的执行记录；启用同步的 ETF 又直接成为策略候选，新增采集对象会意外改变策略。

用户需要可靠地区分正式与暂算的市场判断，在独立页面维护数据，并能知道数据更新是否完成。历史修订后应以修正后的完整历史为准，不需要重放过去网站曾展示的状态。

## Solution

沿用已完成的 Cloudflare Tunnel 和 Zero Trust 登录，提供共享入口和导航的 Candela 网站：

- **市场总览**：中证全指 K 线、MACD、正式与暂算月度牛熊状态，以及各自的策略类型提示。默认近 10 年月线，可切换日／周／月及缩放至全部历史；不提供同步操作按钮，可链接到数据管理。
- **数据管理**：按中证全指、ETF、申万分组管理数据覆盖、增量同步、历史重同步及同步执行记录。支持 ETF 接入和同步开关、取消、恢复、只重试失败对象。
- 保留现有研究页面与机器人功能，避免将数据维护与行情展示放在同一个页面。

## User Stories

1. 作为网站使用者，我希望通过现有 Zero Trust 登录进入统一网站，以便继续使用已经搭建好的访问基础。
2. 作为网站使用者，我希望通过导航分别进入市场总览和数据管理，以便观察行情时不混入维护操作。
3. 作为网站使用者，我希望原有研究页面仍可访问，以便新网站不破坏既有工作。
4. 作为市场观察者，我希望查看中证全指官方日线衍生的 K 线，以便观察整体市场而非某只 ETF。
5. 作为市场观察者，我希望默认看到近 10 年月线并可缩放至全部历史，以便兼顾概览与长期研究。
6. 作为市场观察者，我希望切换日、周、月线时 MACD 同步切换周期，以便研究不同尺度。
7. 作为市场观察者，我希望视窗缩放不改变同一时点的指标值，以便避免截断历史造成误判。
8. 作为市场观察者，我希望明确看到指标预热不足，以便不将缺少历史误认为零值或牛市。
9. 作为市场观察者，我希望看到最新应完成月份的正式状态及月份，以便判断当前已确认的市场环境。
10. 作为市场观察者，我希望同时看到当月未确认的暂算状态及截止日，以便观察月内变化。

12. 作为市场观察者，我希望切换图表周期不改变状态卡的月度口径，以便保持判断标准一致。

14. 作为市场观察者，我希望月中同步失败时保留带截止日的滞后暂算结果，以便了解最后可用信息。
15. 作为市场观察者，我希望更新过程中继续看到上一套完整结果及更新标记，以便避免图表和状态混用不同数据。
16. 作为市场观察者，我希望历史修正成功后所有受影响的后续指标一起更新，以便始终依据修正后的完整历史。
17. 作为数据维护者，我希望按类别查看覆盖起止日期、同步状态和失败原因，以便定位数据问题。
18. 作为数据维护者，我希望新增中证全指和 ETF 时取得源端全部可用历史，以便不被旧的默认起点截断。
19. 作为数据维护者，我希望提交 ETF 代码后校验产品身份，以便不会将非 ETF 加入管理。
20. 作为数据维护者，我希望新增 ETF 只扩大采集范围，以便现有策略的候选和结果不被隐式改变。
21. 作为数据维护者，我希望停用或重新启用 ETF 同步时保留历史，以便控制维护范围。
22. 作为数据维护者，我希望仍被策略使用的 ETF 不允许停用，并显示原因，以便避免策略失去数据更新。
23. 作为数据维护者，我希望按选定对象发起增量同步，以便补齐最新数据。
24. 作为数据维护者，我希望选定日线起止日期重新同步，以便补缺和修正既有数据，同时保留区间外记录。
25. 作为数据维护者，我希望刷新申万字典和成分归属，并同步申万指数日线，以便统一维护现有数据类别。
26. 作为数据维护者，我希望关闭浏览器后同步继续运行，以便不必等待页面请求完成。
27. 作为数据维护者，我希望看到批次与各对象的进度和结果，以便区分成功、失败及尚未处理的部分。
28. 作为数据维护者，我希望重复提交相同未完成请求时复用已有记录，以便避免重复执行。
29. 作为数据维护者，我希望同一数据对象的不同请求排队，以便避免并发写入相互覆盖。
30. 作为数据维护者，我希望取消排队或运行中的同步并保留已写数据，以便停止不再需要的后续工作。
31. 作为数据维护者，我希望机器恢复后自动继续未取消的未完成工作，以便无需重新从头同步。
32. 作为数据维护者，我希望中断与恢复留在执行记录中，以便解释任务耗时和结果。
33. 作为数据维护者，我希望批次中 20 只 ETF 成功 18 只、失败 2 只时只重试这 2 只，以便不重复成功工作。
34. 作为网站使用者，我希望每日北京时间 18:00 自动更新已启用的日线数据，以便不必手动维护。
35. 作为机器人使用者，我希望网站建设后现有信号和每日收盘报告继续工作，以便不破坏既有使用方式。
36. 作为网站所有者，我希望浏览器无需持有内部服务密钥且所有业务路由受保护，以便公网访问不暴露内部接口和数据库。

## Implementation Decisions

### 已确认：数据与计算口径

- 中证全指为独立 Index Series，代码 000985.CSI，日线来自 Tushare index_daily；不使用 ETF 复权因子或盘中快照，也不是申万指数或策略交易候选。
- 中证全指和新接入 ETF 首次回填源端全部可用历史，随后增量更新。不能直接套用旧 ETF 的 2010 年起点；不得将示例 CSV 最早日期或一次空响应当作源端覆盖下界。
- 日线按交易日期升序聚合周／月 OHLC，保留实际数据截止日。周按上海时间自然周、月按自然月聚合；最新未完成周期明确标注。缺失、无效价格不补零，不伪造交易日。
- 各周期 MACD 参数为 12、26、9；DIF = EMA12(close) − EMA26(close)，DEA = EMA9(DIF)，柱 = DIF − DEA，不乘二。EMA 以首个输入值初始化，递推权重为 2/(周期+1)。先计算完整历史，再裁剪展示窗口。
- 各周期前 33 根价格柱不展示 MACD，第 34 根起展示。正式月状态至少需要 34 个有效已完成月；暂算可以使用 33 个已完成月加当前月构成第 34 个输入。阈值是产品约定，不承诺与其他软件的不同初始化算法完全一致。
- 月柱 MACD 大于或等于零为牛市，提示趋势跟踪；小于零为熊市，提示反弹策略。这是人工环境参考，不自动切换策略或下单。

### 已确认：正式、暂算和更新期间的可用性

| 场景 | 正式状态／提示 | 暂算状态／提示与图表 |
| --- | --- | --- |
| 正常月中 | 最新应完成月份的已确认结果，标注月份 | 使用当月最新官方收盘，标注未确认、月份、截止日 |
| 月末最后交易日尚未收盘 | 不提前确认当月 | 可展示已有当月暂算；不读取盘中报价 |
| 最新应完成月缺必要官方日线 | 显示待同步，暂停当前正式策略提示；旧结果仅作注明月份的历史参考 | 保留有效历史图；暂算不能替代缺失的正式结果 |
| 月中更新失败 | 已完整确认的月份仍有效 | 旧暂算保留并标滞后／截止日，不冒充最新 |
| 新月尚无官方日线 | 按应完成月的实际数据判断 | 当月暂无暂算，不能拿上月值冒充当月 |
| 历史不足或数据无效 | 明确不可用及原因，不输出牛熊和提示 | 价格历史可读，指标按有效性和预热规则展示 |
| 同步或重算中 | 可保留上一套完整结果，但待同步等规则仍优先 | 显示更新中；不得混合部分新价格与旧指标 |
| 更新成功 | 以修正后的完整历史重算并整体替换 | 图表与正式／暂算结果使用同一数据版本 |
| 失败或取消 | 标记更新未完成，不发布半套结果 | 保留上一套完整结果并展示实际截止／滞后情况 |

最新应完成月由上海时间、交易日历和收盘时间共同确定；月末遇休市不能硬用自然月最后一天。交易日历不可用时不猜测确认月份。成功发布不保留旧市场状态档案；同步日志与临时展示缓存不属于旧市场状态归档。

### 已确认：数据管理与执行语义

- 中证全指、ETF、申万分类展示；日线提供增量与指定闭区间的历史重同步。申万字典和成分提供刷新动作，不套用无意义的日线日期区间。
- ETF 接入经源端元数据校验，首次全历史同步。同步名单与每个 Strategy Universe 独立；迁移一次性保留现有候选，不因新增或重启自动扩张。
- ETF 停用保留历史，重新启用继续增量；仍属任一策略候选的 ETF 不可停用。首版不提供候选名单编辑页面。
- 历史重同步更新已有记录、补齐缺失记录，保留区间外数据，不先删除再重建。历史修正后重新计算所有受影响的后续 MACD 与状态。
- Sync Run 在后台独立执行，记录原始对象、日期范围、进度、结果、错误和中断／恢复。批次记录汇总结果，每个数据对象可独立成功或失败。
- 同一对象串行，不同请求排队；相同且尚未完成的请求复用记录。提交时固定对象集合与日期边界，恢复时不将“今天”或“全部”重新展开成另一批工作。
- 排队和运行中均可取消，保留已写数据，停止后续处理，最终标记已取消；取消的任务不在重启后复活。请求取消与实际停止之间需显示取消中。
- 服务恢复后自动继续未取消的未完成工作，保留已完成部分。手动失败重试只选择失败对象，原成功对象不重跑，重试记录可追溯到原批次。
- 每日 18:00 Asia/Shanghai 由外部系统 cron 触发启用日线数据的增量任务；自动行情拉取遵循交易日历。现有机器人每天收盘报告保留，非交易日不因此取消报告。

### 已确认：实现方案

- 使用 Go 网站服务承载静态前端与受限的业务 API 转发，只调用 syncer，不直连 MySQL。前端采用 TypeScript、Vite 和 ECharts；图表只渲染服务端已算好的结果。首版不新增消息队列或独立计算服务。
- syncer 对外收敛为“数据维护”和“市场总览查询”两个业务边界，复用已有数据源与存储适配器；持久执行、分段进度、对象互斥、恢复和结果发布隐藏在边界内部。
- MySQL 增加独立指数日线、交易日历、策略归属、同步批次／对象／分段进度及当前发布结果。使用有版本的一次性迁移，特别防止重复初始化策略候选。
- 同步任务先持久接受，再由后台执行；客户端断开只停止等待，不取消任务。旧 HTTP、机器人和 one-shot 入口必须经过相同的执行协调，不能绕过对象互斥。保留收盘报告依赖同步完成后计算的语义。
- 分段原始数据提交与完成检查点需保持事务一致；不能用全表最大日期推断历史重同步进度。取消与写入有明确先后关系，失去执行权的旧进程不能继续提交。
- 市场计算使用一致的原始数据快照及版本，候选结果只在完整成功且版本仍有效时整体发布；不允许较旧的计算覆盖更新的结果。查询再结合当前日历和更新状态判定可用性。
- ADR-0009 明确修订 ADR-0001 的“无状态、无内部调度逻辑”边界：每日触发仍在系统 cron，服务内新增持久执行协调及重启恢复。
- 网站和业务 API 全部经过现有 Access；源站校验 Access JWT 的签名、签发方、目标应用和有效期。仅允许必要业务转发，内部服务密钥不下发浏览器；写操作校验同源并防范 CSRF，日志不记录令牌。具体部署参数在上线时验证，不要求现在提供密钥。

## Testing Decisions

以下测试边界已随本 PRD 获得用户批准。以业务调用者能观察的结果为主，不绑定私有函数、表内部字段或图表库实现；优先使用现有 QuoteSource／Store／SWSource 等适配边界，不为每个小函数增加接口。

| 测试层与主要入口 | 验证结果 |
| --- | --- |
| 数据维护业务入口，复用现有同步测试中的可控数据源 | 全历史覆盖、源端分页／空结果／报错、ETF 校验、分组、指定区间幂等更新与区间外不变 |
| 同一业务入口配合真实测试 MySQL | 重复请求复用、同对象串行、部分成功、仅重试失败 2 只、取消竞态、崩溃恢复、原范围不漂移、旧执行者失权后无法写入 |
| 市场总览查询入口，固定时钟／日历／行情 | 独立预期值核对 EMA 初始化和 MACD；第 33／34 根边界；零柱牛市；日周月切换和缩放不改月状态；历史修正传播到后续月份 |
| 市场查询与数据维护联测，真实测试 MySQL | 同步中、取消、失败、重启和重算期间始终得到一致结果；旧版本不覆盖新版本；历史结果不冒充当前正式状态 |
| 策略原有公开计算链 | 一次性迁移前后候选不变；新增非候选 ETF 仍同步但不参与信号；策略引用阻止停用；重启不重建候选 |
| 少量浏览器端到端测试 | 登录保护、两页面隔离、图表周期与时间范围、缺数提示、提交后刷新仍能查看任务、取消和失败重试操作 |
| 网站访问与兼容性测试 | 拒绝缺失／伪造／过期／错误应用令牌及跨站写请求；内部密钥不出现在前端；机器人旧接口及每日报告行为保留 |

月末测试至少覆盖：最后交易日盘前／收盘后未同步／已同步、月末周末或长假、新月没有数据、月中失败、历史不足、交易日历缺失。真实数据库测试使用隔离测试库，不连接生产库；日常自动测试不依赖实时 Tushare，另做受控的源端权限与响应格式联调。已有 Go 同步、申万、轮动和机器人测试是回归基础。

## Out of Scope

- 重搭 Cloudflare Tunnel、Zero Trust 或证书；本次不接入 Authing、注册、多租户或角色权限系统。
- 自动交易、自动切换策略、真实持仓管理、新的买卖信号规则。
- 策略候选名单的页面编辑；任意新增指数、个股接入或新的数据供应商。
- 旧市场状态版本归档、历史网站状态重放。
- 把全部已有研究页面重写为新前端；另建小市值轮动专用网站。
- 清空或迁移未授权的本地研究数据；合并此前其他工作区尚未迁移的代码。

## Further Notes

- 当前已完成需求和设计确认；业务代码、数据库、cron 与线上服务均未改变，也未执行生产同步。
- 上线前需确认实际 Tushare 账号具有所需权限和历史覆盖；不足时明确报告，不能将权限失败视作“无历史”。ETF 身份校验不能仅凭代码格式或 fund_basic 的“场内”字段。
- 实现依据：index_daily 支持按指数和日期范围读取，且不包含申万日线，因此独立适配两类源。[Tushare 指数日线](https://tushare.pro/document/2?doc_id=95)
- 交易日历提供是否开市及上一交易日，可作为月份完成与数据新鲜度的输入。[Tushare 交易日历](https://tushare.pro/document/2?doc_id=26)
- 推荐 ETF 专属元数据校验，需先核验权限；通用基金列表同时涵盖非 ETF，不可单凭场内市场认定身份。[ETF 基础信息](https://tushare.pro/document/2?doc_id=385)、[基金列表](https://tushare.pro/document/2?doc_id=19)
- EMA 采用首值初始化的递推定义；34 根显示门槛为本项目约定。[pandas EWM 定义](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.ewm.html)
- ECharts 提供缩放、平移及提示组件，适合作为本稿的图表实现选择。[ECharts 功能说明](https://echarts.apache.org/en/feature.html)
- Access 令牌验证方式参照官方说明；这是已确认的源站访问边界方案，不代表已检查用户当前线上配置。[Cloudflare JWT 验证](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)
